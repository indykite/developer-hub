    What this proves, and what it does not
    • Any change to an event, a hash, the order, or a checkpoint is detected: hashes no longer link, or a signature no longer verifies under IndyKite's public key.
    • Re-hashing does not help a forger: SHA-256 can be recomputed by anyone, the ECDSA P-256 signatures cannot without the private key.
    • Completeness is yours to anchor: a chain with its newest batches cut off still verifies. Keep a checkpoint or the newest head you saw (this page remembers it in your browser) and compare.
    • Scope: platform events delivered by the project's event sink while audit signing is configured. Agent Gateway and Token Service audit records go to their own file or webhook and are not in this chain.
    • Keys: IndyKite's platform key signs today; customer-managed keys are not used for signing yet. Keep the JWKS with each export, since rotated keys leave the published set.

    Check an export yourself, without this app: unzip it and run the public audit-verify.py on the folder. See the Audit Log API, Audit Signing and Outbound Events guides on the IndyKite developer site.
