How ContX IQ Works
1. Policy

Defines what data can be accessed and who can access it. Uses Cypher patterns to match graph structures and filters to bind parameters. Specifies allowed reads, upserts, and deletes.

2. Knowledge Query

Defines what data to return from the matched graph. Specifies which node properties and relationships to include in results.

3. Execute

Runs the query with input parameters. The policy validates access, the query retrieves data, and results are returned. Uses the application's credentials for authorization.

Data Capture

Import the active dataset (data/{{ dataset }}/nodes.json and data/{{ dataset }}/relationships.json) into the IndyKite Knowledge Graph (IKG). Creates the dataset's full graph - its entities, relationships and documents, plus the agent-workflow graph (users, workflows wf1-wf3, the indykiteagent* agents with workflow_name / discriminating_property edges) used by the IndyKite Agent Gateway.

Data Schema

The IKG has no up-front schema - it emerges from the captured data. Inspect the observed schema (node types with their properties and counts, and every (source)-[relation]->(target) combination) via GET /data-schema/v1/. Use it to copy exact type and property spellings before authoring Cypher, or to verify a capture landed.
